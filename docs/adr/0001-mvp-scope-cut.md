# MVP is a local, npm-installed CLI with no CI or installer integrations

The MVP ships the rule format, a JSON source, the CLI (`check`, `check --changed`, `explain`, `where`, `annotate`, `context`, file import), two skills installed by hand, and one install channel: npm (plus `cargo install` for contributors). GitHub and GitLab integrations (Action, CI component, SARIF and `github` reporters, workflow generated by `init`), the `rulelink skills` installer, the managed `AGENTS.md` section, the shell and PowerShell installers and the Docker image move to V1 or V2.

The project is run by one person next to other work, and the MVP's exit criterion is that three external developers reach a first clean `check` in under 15 minutes. Each deliverable removed is one less thing to build, mirror and keep working across platforms. A developer who wants `check` in CI writes a workflow that runs `npx rulelink check`; the exit criterion still requires one such run.

## Considered options

- Full MVP as first drafted (two CI deliverables, four reporters, three installers, Docker, skills installer): rejected, too wide for the available time.
- Keep the Action and SARIF, cut only the GitLab component and Docker: rejected, the Action is itself a maintained deliverable with a mirror repository.

## Consequences

- `check --changed` is in the MVP: the agent loop in the consultation skill needs it.
- The `sarif` and `github` reporters wait for the GitHub Action (V2).
- Release pipeline in the MVP: GitHub release archives and the npm package, built by dist (`.github/workflows/release.yml`).
- Amended by [ADR-0004](0004-shell-and-powershell-installers.md): the shell and PowerShell installers ship in the MVP too.
