# The public site is built with Astro and Starlight, reading `docs/public` in place

Spike for ticket #39 of spec #34. Verdict: **go**. The `site/` project builds the public documentation with Astro and Starlight, a pnpm workspace member and a Moon project (`moon run site:build`, about 12 s with a cold dependency install on a warm machine, 14 pages). The production URL, the repository URL and the docs folder are set once in `site/site.config.mjs`.

## What the prototype proves

- **No copy.** A small content loader (`site/src/docs/loader.ts`) wraps Astro's `glob` loader on `../docs/public`. Pages without front matter (the concept pages) get their title from their first H1.
- **Links valid on GitHub and on the site.** Pages keep GitHub-style relative links (`rules-add.md`, `../concepts/rule-format.md`, `../cli/`). A remark plugin rewrites them to routes and fails the build on a link that points to nothing. It also drops the leading H1, which Starlight renders from the title.
- **Mock-up tokens.** `tokens.css` holds the light and dark colour, type, spacing and radius tokens of the mock-up; `theme.css` maps them onto Starlight variables. IBM Plex comes from `@fontsource`. Rule-status and severity colours are carried over but no component uses them yet.
- **Docs and showcase are separate.** Docs code lives in `site/src/docs`, the showcase placeholder in `site/src/showcase`. Only `src/pages/index.astro` ties the showcase to the routes.

## Problems and workarounds

- **`starlight-links-validator` does not work.** It assumes the docs sit in `src/content/docs` and reported every link of `docs/public` as invalid. Replaced by the check in the remark plugin. The GitHub side stays covered by `docs-check`.
- **Starlight also assumes `src/content/docs`** for autogenerated sidebar groups: with pages read from `docs/public` they come out empty, and the build still passes. An earlier version of this record said they worked; that was wrong. `sidebar.mjs` now lists the folders itself, and a test fails on an empty group.
- **Folder links.** `../cli/` is valid on GitHub only if the folder has a README, so `docs/public/cli/README.md` was added; the loader maps any `README.md` to the folder index.
- **Install scripts are blocked by pnpm 10** (`esbuild`, `sharp`). The build works without them; `sharp` is only needed for image optimisation, which the docs do not use yet.
- **Moon does not install Node dependencies.** `site:install` (`pnpm install --frozen-lockfile`) is a dependency of `site:build`. `pnpm` is not on the PATH outside Moon (proto has no pin), so run it through `moon run site:install`.
- **Not tested:** Windows (the build uses only portable paths), the component set of the mock-up, mobile navigation, Pagefind in the browser (the index is built), visual fidelity (no screenshot was compared).

## Recreating the expected layout

Tried after the spike, on a throwaway copy: `site/src/content/docs` as a symbolic link to `docs/public`, still with no copy, and Starlight's own `docsLoader`.

- **Link alone:** the build passes and autogenerated groups fill, but 88 in-page links break without failing the build (the remark plugin no longer recognises the paths), and the CLI index moves from `/cli/` to `/cli/readme/`.
- **To repair:** resolve the real path in the remark plugin, pass `generateId` to `docsLoader` for `README.md`, and change the edit-link base. "Edit this page" still points into `src/content/docs` and would need an override (not tried).
- **Gain:** `starlight-links-validator` then runs, and reports a missing page and a missing heading. It also reported the four valid links to `/cli/` as invalid, which would need an exclusion or another fix (not tried). Grouping the `rules` subcommands still needs custom sidebar code.
- **Risk:** Git needs symbolic link support to check the link out on Windows (not tested).

The link is not adopted for now. It remains an option if the custom sidebar and link code grow.

## CI cost

- `site:build` has `runInCI: false`, so `moon ci` never runs it. `moon run` skips it on a runner too, so the workflows call `moon exec --ignore-ci-checks`. A separate `site` job in `ci.yml` runs it only when `site/`, `docs/public/`, the lockfile or workspace files change, or on `main`.
- A Rust-only pull request pays one checkout and one `git diff` (a few seconds of runner time, no Node, no pnpm, no Astro). The job reports as skipped-successful.
- A pull request touching the docs pays the Node and pnpm toolchain download, `pnpm install` (about 18 s cold) and the build (about 12 s): estimated under two minutes on a runner. This could not be measured on a real runner here.

## Go / no-go

Go. Open points for the follow-up tickets: the Starlight sidebar for nested commands, the missing components (install tabs, status badges, version badge), the mobile navigation, and pinning Node and pnpm in `.prototools` so `pnpm` works outside Moon. With a fixed `src/content/docs` assumption, or the symbolic link above, `starlight-links-validator` could replace the custom check.
